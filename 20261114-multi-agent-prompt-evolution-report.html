3. Phase 1：初期移行と初回実行（47ccea0）

アーキテクチャ転換の判断

Coordinator と Worker は、p1 のブラウザ CDP 方式を踏襲するのではなく、ローカル agy CLI を一時隔離 HOME（0o700、OAuth トークンと settings.json は 0o600、シンボリックリンク拒否）で呼び出す設計を選択しました。

実行権限は agentMode: "plan"、toolPermission: "strict"、enableTerminalSandbox: true、allowNonWorkspaceAccess: false とし、コマンド実行やファイル読み書き・MCP・URL ダウンロードを拒否して Web 検索のみに閉じ込めました。

運用・CSP sandbox 設計

systemd ユーザータイマーは OnCalendar=*-*-* 05:00:00 Asia/Tokyo、Persistent=true、flock -n による二重起動防止で構成しました。サービス側は ProtectSystem=strict と ProtectHome=read-only に加え、書き込み先を daily_research と ~/.local/share/dashboard に限定しています。

Dashboard の CSP sandbox 制約に合わせるため、document.css を <style> へインライン埋め込みし、外部スクリプトや type="module"、localStorage を排した純粋静的 HTML 生成器を実装しました。

初回実行（19 分 39 秒）で露呈した実運用上の課題

Reviewer のセキュリティ・HTML 境界承認を経てコミット（47ccea0）した後、Runner が daily-gemini-research.service を実起動し、14:31:37 から 14:51:16 JST の 19 分 39 秒（01: 4分34秒、02: 4分30秒、03: 5分58秒、04: 4分37秒）で 4 件の完了と Dashboard 配信を確認しました。しかし、生成された HTML と Markdown を精査すると次の 4 点が露呈しました。

  • 03 の .mb-summary 誤抽出：03 のプロンプトに ## 要点サマリー がなく冒頭から ### 論文リストが始まったため、HTML 変換器が最初に見つかった箇条書き（後半の論文メタデータ）をヒーロー要約枠へ吸い上げてしまいました。
  • 二重 <a> タグ化と空 <strong>：Markdown 出力中の [https://...](https://...) に対し、リンク変換後の文字列へ裸 URL の自動リンク正規表現が再度当たり、<a><a>...</a></a> の入れ子が発生しました。
  • LaTeX 記法の生露出：MathJax を読み込まない CSP 準拠 HTML であるにもかかわらず、モデルが出力した $ ightarrow$ がそのまま文字として表示されました。
  • 週次プロンプト由来の重複・水増し：「過去 1 週間」「5〜10 件」「5〜7 件」という指示がそのまま残っていたため、日次で回すと前日と話題が 6/7 重複し、情報薄の日には一般論や捏造を招く構造になっていました。

5. Phase 3：戦略目標レビュー（FDE・自動運転）と改修（77447f1, a644925）

日次バッチとして整った v2 の出力（2026-11-14 再実行版）に対し、Coordinator は本質的な問いを投げました。「この調査結果で、① Google / OpenAI / Anthropic の FDE に転職・活躍できるか、② 自動運転分野でブレイクスルーと大きな実績を生めるか」。これに対し、argon-rev（Gemini 4 Argon Medium）、Codex (gpt-6.1-sol)、p1 上の Claude (fable 5.2) の 3 者が独立に監査を行い（ボード #29, #33）、3 者とも驚くほど一致した構造的欠陥を突き止めました。

3 者が一致して突いた 3 つの核心的欠陥

第一の欠陥は、read_url 不在による表層スニペット断定です。run_daily_research.py は read_url 併用を想定していましたが、実際の agy --mode plan 環境には read_url が提供されておらず、全レポートが search_web のスニペットだけで書かれていました。その結果、Codex Sol は ActWorld-JEPA（arXiv:2611.16579）公式 abstract に書かれていた「NAVTEST の集計フィードバックで最終 Selector を調整した」という決定的条件をレポートが見落としている事実を突きました。同様に Claude Fable 5.2 は、本文未確認のコマンド（Litek8s 等）を「今すぐ試す」と推奨している危険性や、멀티エージェント 等のハングル混入を指摘しました。

第二の欠陥は、観点①（FDE 転職・活躍）におけるエンタープライズ実戦知の欠如です。従来の 01・02・04 は「個人開発者が手元の WSL2 / Jetson でローカル LLM や CLI を動かす視点」に偏り、FDE の本丸である「顧客本番システムの新規構築（0 から 1）と全社展開（1 から 100）」が欠落していました。3 者が指摘した不足は、東京/APAC の 3 社求人と募集状態の追跡、トークン単価ではなく再試行・手戻り・人手確認込みの成功業務 1 件あたり総コスト、正解データがない業務の Eval と OAuth/RBAC 権限継承・監査、そして自身の強み（AV/ML と Jetson とマルチエージェントハーネス）を製造・物理 AI 顧客へつなぐ導線でした。

第三の欠陥は、観点②（自動運転ブレイクスルー創出）における「成功カタログ」止まりです。従来の 03 は論文の主張を並べるだけで、「評価条件の監査（Open-loop L2 ショートカット、NAVSIM v1 の 93〜94 点台での 1pt 未満飽和、navtest と navhard の split 混同）」「悪化指標や失敗モード」「Jetson AGX Thor（10Hz = 100ms 締切）に対する車載計算予算」「候補生成と Selector のどちらがボトルネックかを切り分ける Oracle 実験仮説」「01 の推論最適化や 04 の事後 Judge との異分野 Cross-Pollination」が欠けていました。

解決 1：証拠規律と深掘り検索

build_research_prompt に候補ごとの多段階 search_web 指示を追加し、情報源を [L2: 公式リリース・アブストラクト・仕様確認済] と [L1: 検索断片のみ・詳細未確認] に分離しました。L1 での強い推奨や未確認コマンド掲載、外国語トークン混入を厳禁化しました。

解決 2：01–04 の実戦化と 05 新設

01 に業務完了単価と FDE 顧客導入・システム設計への示唆 を追加し、04 の応用先を 5a（CLI ハーネス）と 5b（FDE 顧客業務・AD 転用）へ分割しました。さらに統合戦略プロンプト 05-fde-career-and-av-breakthrough-synthesis.txt を新設しました。

解決 3：AD 監査 6 項目と仮説設計

03 に量産 E2E プレイヤーと Embodied AI 転用枠を加え、必須 6 項目（再現資産実体、ボトルネック、評価監査、失敗モード・悪化指標、車載計算予算、Oracle 含む反証仮説）と末尾の Cross-Pollination セクションを組み込みました。

運用堅牢化の仕上げ：PTY 切断による状態上書きバグの発見と修正（a644925）

Phase 3（77447f1）の全 5 本本番実行の最終盤（20:50 JST）、サーバー再起動に伴ってバックグラウンド実行中の PTY が切断されました。このとき、新規 05 は Markdown（44.9 KB）と HTML（69.2 KB）の書き出しおよび save_state(completed) を完了していましたが、直後の print("[ok] ...") が OSError: [Errno 5] Input/output error を送出したため、外側の except Exception: に捕捉されて state.json 上の 05 が failed へ上書きされる事象を Coordinator が発見しました（#47）。

この不具合に対し worker-v3 は、標準出力・標準エラーの BrokenPipeError と OSError を握りつぶす _safe_log() ヘルパーを導入して [ok] ログを try ブロック外の else: へ移動させ、さらに rerender_daily_reports 実行時に既存の state.json を completed（error: null）へ同期修復する _build_prompt_state() を実装しました（a644925）。
