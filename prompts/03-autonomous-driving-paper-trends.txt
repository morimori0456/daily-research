# 自動運転 論文トレンド・評価監査・ブレイクスルー調査

【目的】
自動運転（Autonomous Driving）および車載知能化（End-to-End 運転、VLM / VLA、World Model、閉ループ評価・強化学習、3DGS シミュレータ / Sim2Real、データ合成・蒸留、安全論証等）に関する最新論文・技術公開を日次でキャッチアップし、**単なる主張の要約ではなく「既存ボトルネックの解剖・評価条件の監査・車載計算予算・反証/転用実験仮説」**まで踏み込んだ構造化レポートを作成してください。

【探索対象・情報源】
- **プレプリント / 論文フィード**: `arXiv cs.CV` / `arXiv cs.RO`（`/list/cs.CV/new`, `/list/cs.RO/new` 等）, Hugging Face Daily Papers, GitHub（実装・モデルウェイト・評価スクリプト公開）
- **主要カンファレンス関連**: CVPR, ICCV, ECCV, NeurIPS, CoRL, ICRA, IROS, IV, RSS（採択公開・公式コード公開・カメラレディ改訂等）
- **主要プレイヤー・量産・E2E 実戦エコシステム**: `NVIDIA`, `Waymo`, `Tesla`, `Zoox`, `Li Auto`, `Huawei`, `Wayve`, `Momenta`, `Horizon Robotics`, `Xpeng`, `comma.ai`, `Tier IV`（Autoware）等の公開論文・技術レポート・オープンソース・安全論証（UNECE / SOTIF）
- **隣接・異分野転用対象**: **Embodied AI / Robotics VLA / World Model 基礎**で自動運転の End-to-End プランニング、閉ループ学習、または車載推論に転用可能な研究（毎回関連があれば1件まで探索・比較対象に含める）

【探索期間と採用区分・厳選基準】
- **最優先**: 直近24〜48時間に公開された新規論文、重要な改訂版（v2以降）、または論文に伴う新たな公式実装/ウェイト公開。
- **遅延許容**: 検索インデックス遅延等を考慮し、直近7日以内の未掲載重要論文は「`【遅延発見】`」として許容します。
- **採用基準**: 単なる新着順ではなく、**「既存ボトルネックへの寄与・構造的意義」**を軸に **最大3〜5件** に厳選してください（該当が少ない日は **0〜3件・0件も正常結果として許容**）。
- 各項目は必ず「**新規公開**」「**重要改訂**」「**新たな実装公開**」「**【遅延発見】**」「**【続報】**」のいずれかで区分してください。
- **深掘り検索の徹底**: 1回の検索で終わらせず、採択候補ごとに `search_web` で「`論文ID + limitation / ablation / navtest / navhard / latency / parameters / github`」等の追加クエリを実行し、評価条件・失敗モード・計算量を掘削してください。
- **コミュニティ指標・議論（HF Upvotes / HN / Reddit / X）の扱い（監査独立性の厳守）**:
  - ランナー注入の HF Daily Papers `upvotes`（**10未満は必ず「参考値」と表記し「話題・注目」等と誇張しない**）および HN スコアは、同一 arXiv ID / URL の項目にのみ引用できます。
  - 上位3論文程度（各1〜2クエリまで）について、`search_web` で Reddit（`r/selfdrivingcars`, `r/MachineLearning`, `r/robotics` 等）および X（`"x.com" OR "twitter.com" OR "on X"` + 論文名/arXiv ID）を追加検索し、技術的評価や批判（実車適用への疑問・再現性報告等）があれば URL 付きで付記してください（検索しても該当なし時は「検索結果では未確認」とし末尾の `## コミュニティ探索メモ` に記載。URL なき「X で話題」は禁止）。
  - **重要ガードレール**: **評価監査（Evaluation Audit）の判定根拠にバズ指標（HF Upvotes / HN / Reddit / X）を絶対に使わないでください**。また、自動運転論文は HN/HF に載りにくいため、**バズ不在を不採択や低優先の理由にしない**でください。

【各論文の必須項目（全6項目）】
1. **基本情報・再現資産**
   - 発表日・版（`初版 v1` / `改訂 v2` / `会議公開` を区別）、arXiv ID、URL、著者/組織。
   - **再現資産の実体確認**: コード・学習済み重み（checkpoint）・評価スクリプトの公開有無を分離し、「URL 記載のみ」か「リポジトリ・重み・eval スクリプトの実在を確認できたか」を明記してください（未確認は「未確認」）。
2. **攻めているボトルネックと技術の核心**
   - ボトルネックタグ（例: `[軌道選択/Reranking]`, `[閉ループ学習]`, `[車載VLA効率化]`, `[Sim2Real/3DGS]`, `[長尾OOD/安全制約]`）を付記し、既存スタックのどの構造的課題をどの機構で解いたかを説明してください。
3. **評価条件の監査（Evaluation Audit）**
   - **評価パラダイムの分離**: Open-loop（例: nuScenes L2）か、Closed-loop（例: Bench2Drive / CARLA / HUGSIM / 3DGS）か、疑似閉ループ/スコア評価（例: NAVSIM）か、実車かを明確に分離し、同一の「安全性向上」として混同しないでください。
   - **データセット・split の厳格明記**: 使用データセット・split（例: `navtest` vs `navhard` vs `navhard-two-stage`）を明記し、**異なる split 間のスコアは直接比較不可**と注記してください。
   - **監査チェック**: テストセット集計フィードバックによるハイパラ/Selector 調整（例: `navtest` 集計フィードバック調整）や Privileged info（特権情報）の有無、候補軌道数・探索予算・調整予算、同条件ベースライン比の差分（Δ）を確認してください。
   - **評価妥当性への批判的チェック**:
     - `Open-loop L2 error` が自車状態（Ego-status）のショートカット学習で最適化できてしまう罠への注意。
     - `NAVSIM v1`（93〜94点台）における **1pt 未満の飽和** に対する有意性・実効性の吟味。
4. **限界・失敗モード・悪化指標（Failure Modes & White Space）**
   - 著者が認める限界、悪化または未改善のシナリオ・指標、独立再現や GitHub issue で報告された問題（未確認なら「未確認」）。
   - **前提崩壊ポイント**: どの強い前提（完璧な HD Map、V2X 通信遅延ゼロ、非反応的背景交通、完全なセンサー同期等）が崩れると破綻するかを言語化してください。
5. **車載計算制約（On-vehicle Compute Budget）**
   - 「推論時オーバーヘッドゼロ」等の差分主張がある場合でも、**Base VLM / World Model を含めた総パラメータ数**、入力解像度・トークン数、推論精度（FP16/BF16/FP8/INT4）、推論レイテンシ（ms / FPS、可能なら P99）・ピークメモリを分離確認してください。
   - **`Jetson AGX Thor` 等の車載 SoC のリアルタイム締切（例: 10Hz = 100ms / 20Hz = 50ms）に対するギャップ**を評価してください（未確認の数値は推測せず「未確認」と明記）。
6. **反証・転用実験仮説（Falsifiable Hypothesis）**
   - 公開コードや手元ログで試せる最小の検証実験を1つ定義してください（例：「候補生成がボトルネックか Selector がボトルネックかを切り分ける **Oracle Selector 比較実験**（固定候補集合で現行 Selector vs 最良候補を選ぶ Oracle Selector vs 候補数増を比較）」、あるいは `01`/`04` の LLM Agent 事後 Judge / Reward Hacking 検出 / FP8 KV cache 量子化技術の転用実験）。
