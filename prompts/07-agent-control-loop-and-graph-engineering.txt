# Agent 制御構造（Loop / Graph Engineering）論文・OSS 設計動向調査

【目的】
LLM / マルチモーダル Agent における**反復・探索・停止の制御（Loop）**および**トポロジ・状態遷移・知識構造（Graph）**に関する最新論文・公式技術レポート・主要 OSS フレームワークの制御モデル変更を調査してください。
Context & Memory やサンドボックス実行環境そのものを主軸とする研究はテーマ `04` の担当であるため本レポートでは採用せず、**「Agent がどう回り、どう分岐・協調・停止し、どう構造化知識を辿るか」**という制御構造のブレイクスルーを漏れなく捕捉してください。

【対象範囲とテーマ境界】
- **対象論文・プレプリント**: `arXiv`（`cs.AI`, `cs.CL`, `cs.MA`, `cs.IR`, `cs.SE`, `cs.LG`）、Hugging Face Papers / alphaxiv、NeurIPS / ICLR / ICML / ACL / EMNLP 等。
- **対象公式ブログ・主要 OSS フレームワークの制御モデル変更（リリースノート / 設計ドキュメント / CHANGELOG）**:
  - `LangGraph`, `GraphRAG` (Microsoft), `LightRAG`, `Graphiti`, `AutoGen / AG2`, `Microsoft Agent Framework`, `OpenAI Agents SDK`, `Google ADK`, `CrewAI Flows`, `LlamaIndex Workflows`, `Pydantic AI`, `DSPy`, `Temporal` 等。
- **他テーマとの境界**:
  - 単体 CLI / 開発ツールの紹介やセットアップ手順は `02` の担当。状態グラフの意味論・チェックポイント・`interrupt` / durable execution・並列実行モデル・トポロジ制御の設計変更を `07` で扱う。
  - コンテキストの中身・記憶表現やサンドボックス隔離自体が主軸のものは `04` の担当（`04` 当日・直近7日間の既出 ID/URL は重複排除リストで除外）。

【探索手順（2段階探索・順序厳守）】
**必ず Phase A（発見）を全8サブ領域で完了してから Phase B（深掘り）に進んでください。**
発見クエリには `"loop engineering"` / `"graph engineering"` というバズワードを使わず、実論文・実OSSで使われる以下の語彙と鮮度トークン（`{{FRESHNESS_HINT}}`）を組み合わせて `search_web` で検索してください（`site:` 演算子がヒットしない場合は演算子を外して再検索すること）。

- **Phase A（発見: Loop 4サブ領域 × 計6クエリ以上、Graph 4サブ領域 × 計6クエリ以上）**:
  - **Loop サブ領域**:
    - `L1` 推論時探索: `test-time scaling`, `test-time compute`, `inference-time search`, `MCTS / tree search + LLM agent`, `adaptive thinking budget`
    - `L2` 自己修復・検証ループ: `self-refinement`, `self-correction`, `generate-verify-revise`, `verifier / critic loop`, `evaluator-optimizer`, `failure recovery`, `rollback / checkpoint`
    - `L3` 収束・停止・予算制御: `early stopping / termination criteria`, `"when to stop"`, `budget-aware / cost-aware agent`, `loop detection`, `stuck agent`, `diminishing returns of iteration`
    - `L4` 長時間自律・HITL: `long-running agents`, `long-horizon autonomy`, `outer loop / inner loop`, `autonomous research loop`, `human-in-the-loop interrupt / approval`
  - **Graph サブ領域**:
    - `G1` マルチエージェント・トポロジ: `multi-agent topology`, `communication graph`, `topology optimization`, `agent pruning`, `orchestrator-worker`, `handoff`
    - `G2` ワークフロー生成・DAG: `agentic workflow generation / optimization`, `automated design of agentic systems`, `task graph`, `DAG planning`, `parallel tool-call scheduling`
    - `G3` 状態遷移・耐久実行: `state machine / statechart agent`, `durable execution`, `checkpointing`, `stateful graph`, `workflow engine`
    - `G4` 知識構造・グラフ記憶: `GraphRAG`, `knowledge graph RAG`, `graph memory`, `temporal knowledge graph`, `code graph / repository graph`, `KG-augmented agent`

- **Phase B（深掘り）**:
  - Phase A で採用候補に絞った項目のみ、`search_web` で `論文ID / OSS名 + ablation / limitation / benchmark / release notes / github` を追加検索して詳細・制約を掘削してください。
  - **コミュニティ議論（HN / HF Upvotes / Reddit / X）の統合ルール**:
    - ランナー注入の HN スコア（`points` / `comments`）および HF Daily Papers `upvotes`（**10未満は「参考値」と表記**）は、**Phase A（発見）の補助および「コミュニティ反響」欄の実測値引用にのみ使用**してください（同一 ID・URL にのみ紐付け可、数値創作・流用禁止）。
    - **予約枠保護と上限**: バズ指標は **Loop 1枠・Graph 1枠の最低予約枠を絶対に消費させず**、バズ起点の採択は全体で**最大2件まで**とします。また、技術論文・OSS設計変更は HN/HF に出ない日も多いため、**バズ不在を不採択理由にしない**でください。
    - 上位3項目程度（各1〜2クエリまで）について、`search_web` で Reddit（`r/MachineLearning`, `r/LangChain`, `r/LocalLLaMA` 等）および X（`"x.com" OR "twitter.com" OR "on X"` + 論文/OSS名）を追加検索し、実装上の賛否・批判・落とし穴を URL 付きで整理してください（URL なき「X で話題」は禁止、検索して該当なし時は「検索結果では未確認」とし `## コミュニティ探索メモ` へ記録）。
    - 最終的な採用可否は必ず公式リリース・arXiv 等の `[L2]` 一次裏付けに基づいて判定してください。
- **用語ウォッチ（別枠・各1回のみ）**:
  - 発見クエリとは別に、`"loop engineering"` と `"graph engineering"` を各1回だけ検索し、主枠には採用せず `## 用語ウォッチ` で「誰がどの意味で使い始めているか」を1〜2行で報告してください（ヒットなしなら「新出の動き未確認」と記載）。

【採用枠・予約枠・主軸一意決定規則】
- **採用枠**: **最大3〜5件**（原則4件、該当が少ない日は **0〜3件・0件も正常結果として許容**）。
- **最低予約枠**: うち **Loop 1枠・Graph 1枠を最低予約枠** とします。`[L2: 公式リリース・アブストラクト・仕様確認済]` を満たす候補が存在しない柱は「**空席（該当 L2 なし）**」のままにして他柱で埋めないでください（空席の柱には「次点（`[L1]`・未確認）」を1行だけ付記可）。
- **主軸一意決定規則（「操作している変数」で1つに決定し、副タグは別欄へ）**:
  - 操作している主変数が「反復・停止・探索・検証の制御」→ **主軸: `Loop`**
  - 操作している主変数が「トポロジ・状態遷移・ワークフロー構造・知識グラフ構造」→ **主軸: `Graph`**
