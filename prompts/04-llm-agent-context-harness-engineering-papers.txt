# LLM・Agent技術・Context/Harness Engineering 論文・技術レポート調査

【目的】
直近24〜48時間（インデックス遅延等を考慮し、直近7日以内の未掲載重要項目は「`【遅延発見】`」として許容）で公開された、LLM の入出力・記憶制御および Agent の実行・評価・制御基盤（Context Engineering / Harness Engineering 等）に関する論文・公式技術レポートを調査し、**個人の CLI ハーネス運用・FDE エンタープライズ顧客業務・自動運転開発パイプラインの3軸**に接続した構造化レポートを作成してください。

【対象外・スコープ境界】
- 一般的な基礎モデルの事前学習（Pre-training）やパラメータスケーリング則そのものを主眼とする論文は除外してください。
- 推論エンジンの運用 Tips・一般モデル更新は別テーマ（01）、開発ツール単体の紹介は別テーマ（02）で扱うため、本レポートは**Agent アーキテクチャ、Context/Memory 制御、実行ハーネス/サンドボックス、評価・検証手法の設計と定量的実証**に集中してください。

【対象とする技術領域とキーワード】
キーワードの名称一致だけでなく、解決する課題・システム設計・実証評価の中身で採否を判断してください。

1. **Context Engineering（文脈・記憶・プロンプト構造の最適化）**
   - 例: In-Context Learning (ICL) の動的最適化、階層型/長期メモリ（Hierarchical / Long-term Memory）、Long-context の効率化、Context Compression（文脈圧縮）、KV-Cache の構造化・最適化、Dynamic Prompting、高度な RAG 制御
2. **Harness Engineering（Agent 実行環境・サンドボックス・評価基盤）**
   - 例: Agent Harness Design、Sandboxing（安全なコード・ツール実行・権限境界・Reward Hacking 防御）、Test-time Compute / Reasoning の制御ラッパー、LLM-as-a-Judge / Evaluator Harness、ベンチマーク環境（SWE-bench, WebArena 等）の構築・厳格化手法、決定的テストと非決定的評価の統合
3. **Loop Engineering（反復試行・自己修復・推論ループの制御）**
   - 例: Agent execution loop（実行・フィードバック・再試行制御）、Self-Correction / Reflection loop（自己修正・リフレクション）、Test-time Search / MCTS（モンテカルロ木検索）などの推論時ループ、Human-in-the-loop（人間の介入制御）、無限ループ防止・早期終了・予算制御アルゴリズム
4. **Graph Engineering（グラフ構造によるワークフロー・協調・知識表現）**
   - 例: Graph-based Agent Workflow / DAG（有向非巡回グラフ）制御、Graph-of-Thought (GoT)、Multi-Agent Collaboration Graph（複数 Agent の相互作用グラフ）、Knowledge Graph + RAG (GraphRAG)、State Graph（状態遷移エンジニアリング）
5. **新出の「〜 Engineering」（実体のある技術手法のみ）**
   - 例: **Flow Engineering**, **Memory Engineering**, **Tool Engineering**, **State Engineering** 等。
   - **採用条件**: 単なるブログの造語・バズワード記事や既存手法の言い換えだけの記事は**除外**し、**具体的なシステム設計・実装・定量的評価を伴う論文または公式技術レポートのみ**に限定してください。

【採用件数の方針】
- 本日のピックアップは**最大3〜5件**に厳選してください。
- 該当が少ない日は無理に件数を埋めず、**0〜3件（該当なし・0件も正常結果として許容）**で構いません。

【各項目についてまとめる内容】
1. **タイトル・発表日・著者/組織・URL・arXiv ID（該当する場合）**
2. **資料種別・コード公開有無**
   - 資料種別を「査読論文（会議/ジャーナル名）」/「プレプリント（arXiv）」/「公式技術レポート・Engineering Blog」から明記し、コード・ベンチマーク公開の有無を記載してください。
3. **解決する課題とアーキテクチャ**
   - 何がボトルネックであり、どのような構造・アルゴリズム・制御機構を提案しているか。
4. **評価条件と定量的効果・限界**
   - 使用ベンチマーク・ベースライン・測定条件、確認できた定量的改善値、および著者らが挙げている限界・制約事項。
   - **厳格化ルール**: 統計的有意検定が `[L2: 公式リリース・アブストラクト・仕様確認済]` で確認できていない場合に「有意に抑制」等と表現することや、実験対象外のモデルへ過度に一般化することを禁止します。未確認の数値やSNS反響は「未確認」と明記してください。
5. **応用・転用の2軸分析（両方必須・論文実証事実と設計考察を分離）**
   - **5a. 自身のマルチエージェント / CLI ハーネス運用（Claude Code / Codex / Antigravity）への応用**:
     - サンドボックス隔離実行環境・コンテキスト管理・権限境界・評価・ループ制御への具体的な応用示唆。
   - **5b. FDE エンタープライズ顧客業務・または自動運転開発パイプラインへの転用**:
     - **顧客業務転用の場合**: 対象業種・ワークロード、本番 Eval 指標、認可継承（RBAC/OAuth）・データ所在・監査ログ・書込副作用で壊れる前提、人間へのエスカレーション・引継ぎ設計。
     - **自動運転開発パイプライン転用の場合**: 閉ループ学習・評価ハーネス、事後 Judge による軌道/方策評価、Reward Hacking 検出、運転経験メモリの記憶退行防止などへの転用条件と最初に崩れる前提。
