# Agent Context & Harness Engineering 論文・技術レポート調査

【目的】
直近24〜48時間（インデックス遅延等を考慮し、直近7日以内の未掲載重要項目は「`【遅延発見】`」として許容）で公開された、LLM Agent の **Context & Memory Engineering** および **Harness & Execution Engineering** に関する論文・公式技術レポートを調査し、個人の CLI ハーネス運用・FDE エンタープライズ顧客業務・自動運転開発パイプラインに接続した構造化レポートを作成してください。
さらに末尾の「拡張枠（最大1件）」では、ランナーから曜日別ローテーションで指定される隣接領域（Agentic Post-Training/蒸留、Eval/Security、Multimodal/World-Grounded Agents）の重要研究を1件まで追跡します。

【対象外・スコープ境界】
- **Loop / Graph 制御構造の分離**: 反復制御・収束/予算制御・Test-Time Search/MCTS（Loop）および Multi-Agent Topology・DAG・状態機械・GraphRAG/KG（Graph）を主軸とする論文・OSS設計変更は別テーマ（`07`: Agent 制御構造）で専任調査するため、本レポート（`04`）の本枠では採用しません（主軸判定：操作している変数が「コンテキストの中身・記憶」または「実行環境・ツール・権限・評価器」であるものを `04` とします）。
- 単純な基礎モデルの事前学習スケーリング則のみを主眼とする論文は除外し、推論エンジン一般運用 Tips は `01`、開発ツール単体紹介は `02`、自動運転ドメイン論文は `03`・`06` に譲ります。

【本枠の対象領域（2本柱）】
キーワード一致ではなく、解決する課題・操作している変数・定量的実証の中身で採否を判断してください。

1. **Context & Memory Engineering（文脈・記憶の編成と最適化）**
   - 例: 長期記憶（Hierarchical / Episodic Memory）、証跡リンク型メモリ（Evidence-Linked Memory）、文脈圧縮（Context Compression）、KV-Cache 構造化・再利用、Dynamic Prompting、ファイル操作ベースの長期記憶維持
2. **Harness & Execution Engineering（実行基盤・ツール境界・評価ハーネス）**
   - 例: ツール合成・スキーマ最適化、サンドボックス隔離実行制御、権限境界設計、Evaluator Harness（決定的テストと非決定的評価の統合、LLM-as-a-Judge 安定化）

【拡張枠（曜日ローテーション対象・最大1件）】
- 本日の拡張枠対象は、以下の通り実行日付の曜日（JST）に応じてランナーが動的に指定します（月木: Agentic Post-Training & 蒸留 / 火金: Evaluation, Reliability & Security / 水土: Multimodal & World-Grounded Agents / 日: 拡張枠なし）。

【採用件数の方針】
- 本枠は **2〜4件**（該当が少ない日は 0〜2件も許容）、拡張枠は **最大1件**（日曜または該当なしは0件）、合計 **最大3〜5件** に厳選してください（該当が少ない日は **0〜3件・0件も正常結果として許容**）。

【各項目についてまとめる内容】
1. **タイトル・発表日・著者/組織・URL・arXiv ID（該当する場合）**
2. **資料種別・コード公開有無**
   - 資料種別を「査読論文（会議/ジャーナル名）」/「プレプリント（arXiv）」/「公式技術レポート・Engineering Blog」から明記し、コード・ベンチマーク・重み公開の有無を記載してください。
3. **主軸と副タグ・解決する課題とアーキテクチャ**
   - 主軸を「操作している変数」で `Context` / `Harness`（拡張枠は指定領域）のいずれか1つに一意決定し、副次的に関わる要素は `副タグ` に記載してください。
4. **評価条件と定量的効果・限界**
   - 使用ベンチマーク・ベースライン・測定条件、確認できた定量的改善値、および著者らが挙げている限界・制約事項。
   - **厳格化ルール**: 統計的有意検定が `[L2: 公式リリース・アブストラクト・仕様確認済]` で確認できていない場合に「有意に抑制」等と表現することや、実験対象外のモデルへ過度に一般化することを禁止します。未確認の数値や SNS 反響は「未確認」と明記してください。
5. **応用・転用の2軸分析（論文実証事実と設計考察を分離）**
   - **5a. 自身のマルチエージェント / CLI ハーネス運用（Claude Code / Codex / Antigravity）への応用**:
     - サンドボックス隔離実行・コンテキスト/証跡メモリ管理・権限境界・評価への具体的な応用示唆（実証事実と設計考察を分離）。
   - **5b. FDE エンタープライズ顧客業務・または自動運転開発パイプラインへの転用（どちらか一方を簡潔に3〜5行以内）**:
     - 対象ワークロード / ADパイプライン、本番 Eval 指標、壊れる前提（認可 RBAC/OAuth・データ所在・監査ログ・書込副作用・閉ループ仮定）、人間エスカレーション・引継ぎ設計。
